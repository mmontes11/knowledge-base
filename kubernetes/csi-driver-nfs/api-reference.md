# csi-driver-nfs — API reference

The project defines **no custom API group and no CRDs of its own**: its API surface is the CSI plugin `nfs.csi.k8s.io` (controller + node plugin) together with the standard Kubernetes kinds it provisions and consumes. The only CRDs involved are the upstream external-snapshotter `snapshot.storage.k8s.io/v1` kinds, installed optionally by the chart. The canonical in-repo reference is [docs/driver-parameters.md](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/docs/driver-parameters.md).

## Kinds provisioned or consumed by the CSI plugin

| Kind | API group/version | Purpose | Upstream API docs |
| --- | --- | --- | --- |
| `CSIDriver` | `storage.k8s.io/v1`, name `nfs.csi.k8s.io` | Driver object: `attachRequired: false`, `volumeLifecycleModes: [Persistent]` (plus `Ephemeral` when the chart value `feature.enableInlineVolume` is on), and `fsGroupPolicy: File` by default (`feature.enableFSGroupPolicy: true`) so the kubelet can chown the mount root | [CSIDriver template](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/charts/latest/csi-driver-nfs/templates/csi-nfs-driverinfo.yaml) |
| `StorageClass` | `storage.k8s.io/v1`, provisioner `nfs.csi.k8s.io` | Dynamic provisioning; required `parameters.server` (NFS address) and `parameters.share` (export path); optional `parameters.subDir` (auto-created, supports `${pvc.metadata.name}`, `${pvc.metadata.namespace}`, `${pv.metadata.name}` tokens), `parameters.mountPermissions` (chmod after mount), `parameters.onDelete` (`delete` default / `retain` / `archive`) | [driver parameters](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/docs/driver-parameters.md), [example StorageClass](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/deploy/example/storageclass-nfs.yaml) |
| `PersistentVolume` / `PersistentVolumeClaim` | `v1` | Static provisioning: mandatory `spec.csi.volumeHandle` (recommended format `{nfs-server-address}#{share-name}#{sub-dir-name}`) plus `volumeAttributes.server`, `volumeAttributes.share`, optional `volumeAttributes.mountPermissions`; for dynamic volumes the driver writes the `volumeHandle` in the same `#`-separated element order (with trailing `onDelete`/UUID elements) | [driver parameters](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/docs/driver-parameters.md), [PV example](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/deploy/example/pv-nfs-csi.yaml) |
| `VolumeSnapshotClass` | `snapshot.storage.k8s.io/v1`, driver `nfs.csi.k8s.io` | Mandatory `deletionPolicy` (`Delete`/`Retain`); optional `parameters.server`/`parameters.share` (default: the source volume's), and `parameters.mountOptions` (since v4.11.0) applied when the controller mounts the share to create the snapshot | [driver parameters](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/docs/driver-parameters.md), [snapshot example](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/deploy/example/snapshot/README.md) |
| `VolumeSnapshot` / `VolumeSnapshotContent` | `snapshot.storage.k8s.io/v1` | Standard external-snapshotter API; each snapshot is stored on the NFS share as a `.tar.gz` archive (`.tar` when compression is disabled, since v4.13.0); the chart creates these CRDs only when `externalSnapshotter.customResourceDefinitions.enabled` is true | [snapshot example](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/deploy/example/snapshot/README.md), [CRD template](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/charts/latest/csi-driver-nfs/templates/crd-csi-snapshot.yaml) |

## Objects deployed by the Helm chart / kubectl manifests

| Object | Kind / name | Purpose | Upstream docs |
| --- | --- | --- | --- |
| Controller | `Deployment` `csi-nfs-controller` | Controller-side CSI plugin with `csi-provisioner`, `csi-resizer`, `csi-snapshotter`, `livenessprobe` sidecars; runs with `--leader-election`, `--extra-create-metadata=true` and the flags `--default-ondelete-policy`, `--use-tar-command-in-snapshot`, `--enable-snapshot-compression` (see [controller template](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/charts/latest/csi-driver-nfs/templates/csi-nfs-controller.yaml)) | [chart values](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/charts/latest/csi-driver-nfs/values.yaml) |
| Node | `DaemonSet` `csi-nfs-node` (node-driver-registrar + livenessprobe) | Node-side CSI plugin; Linux-only (`kubernetes.io/os: linux` selector), `hostNetwork: true` (upstream notes NFS connections break without it); chart value `driver.mountPermissions` is threaded into `--mount-permissions` | [node template](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/charts/latest/csi-driver-nfs/templates/csi-nfs-node.yaml) |
| External snapshotter controller | `Deployment` `snapshot-controller` (optional) | Cluster-wide external-snapshotter controller; off by default (`externalSnapshotter.enabled: false`), enable it in the chart when using snapshots | [chart values](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/charts/latest/csi-driver-nfs/values.yaml) |
| ServiceAccounts + RBAC | `csi-nfs-controller-sa`, `csi-nfs-node-sa` | API permissions for provisioner/resizer/snapshotter operations | [RBAC templates](https://github.com/kubernetes-csi/csi-driver-nfs/tree/master/charts/latest/csi-driver-nfs/templates) |
| Storage/instance resources | `StorageClass` (optional, `storageClass.create` / `storageClasses.create` for multiple), `VolumeSnapshotClass` (optional, `volumeSnapshotClass.create`) | Chart can create the provisioned `StorageClass` (server/share parameters) and the `VolumeSnapshotClass` for you | [chart values](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/charts/latest/csi-driver-nfs/values.yaml) |
| Secrets (user-provided) | any name | Private-registry image pulls (`imagePullSecrets`), and the documented workaround for passing `mountOptions` into `DeleteVolume`/`DeleteSnapshot` via the `csi.storage.k8s.io/provisioner-secret-name`/`-namespace` and `csi.storage.k8s.io/snapshotter-secret-name`/`-namespace` parameters | [driver parameters](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/docs/driver-parameters.md) |

## Notes

- Volume ID (`volumeHandle`) format is `{nfs-server-address}#{share-name}#{sub-dir-name}` — e.g. `nfs-server.default.svc.cluster.local/share#subdir#` — with dynamically provisioned volumes appending `onDelete` and UUID elements in fixed positions ([volume id ordering in the controller](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/pkg/nfs/controllerserver.go)).
- The repository maintains versioned installs in two parallel trees: Helm charts under [`charts/vX.Y.Z/`](https://github.com/kubernetes-csi/csi-driver-nfs/tree/master/charts) (plus `charts/latest/`) and raw manifest sets under [`deploy/vX.Y.Z/`](https://github.com/kubernetes-csi/csi-driver-nfs/tree/master/deploy), with per-version install guides in [docs/](https://github.com/kubernetes-csi/csi-driver-nfs/tree/master/docs).
- The CSI spec conformance level tracks the driver release: CSI spec `v1.10.0` as of v4.10.0 ([#796](https://github.com/kubernetes-csi/csi-driver-nfs/pull/796)).
- Troubleshooting: upstream [CSI driver troubleshooting guide](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/docs/csi-debug.md); project support via sig-storage ([support.md](https://github.com/kubernetes-csi/csi-driver-nfs/blob/master/support.md)).
