# nvidia-device-plugin — features

Key capability areas, each linked to the upstream documentation that covers it in depth. The repository [README](https://github.com/NVIDIA/k8s-device-plugin#readme) is the authoritative, always-current reference; version-specific behaviour is in the [releases](https://github.com/NVIDIA/k8s-device-plugin/releases).

- **GPU resource exposure**: registers `nvidia.com/gpu` (and, when MIG is enabled, MIG-sliced resources) with the kubelet so the scheduler can place GPU workloads. Device lists are handed to the container runtime via a configurable `DEVICE_LIST_STRATEGY` (`envvar`, `volume-mounts`, `cdi-annotations`, `cdi-cri`) and device identity via `DEVICE_ID_STRATEGY` (`uuid` or `index`). [running GPU jobs](https://github.com/NVIDIA/k8s-device-plugin#running-gpu-jobs), [configuration option details](https://github.com/NVIDIA/k8s-device-plugin#configuration-option-details)
- **MIG (Multi-Instance GPU) support**: `MIG_STRATEGY` of `single`, `mixed`, or `none` splits qualifying GPUs into independently-schedulable compute instances; `mixed` exposes each MIG slice type as its own resource (suffixed profiles exposed separately since v0.20.0). [MIG section](https://github.com/NVIDIA/k8s-device-plugin#configuration-option-details), [v0.20.0 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.20.0)
- **GPU sharing / time-slicing**: `sharing.timeSlicing` (and the experimental CUDA `mps` path) replicates a resource `N` times (`replicas`) so more containers than physical GPUs can schedule onto a node; `renameByDefault` emits `.shared` resource names and `failRequestsGreaterThanOne` can limit whole-GPU requests. [shared access to GPUs](https://github.com/NVIDIA/k8s-device-plugin#shared-access-to-gpus), [with CUDA MPS](https://github.com/NVIDIA/k8s-device-plugin#with-cuda-mps)
- **Allocation policy**: since v0.20.0 the plugin's replicated/MIG allocation mode (packed vs. distributed) is configurable; distributed placement breaks ties by preferring distinct physical GPUs. [v0.20.0 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.20.0)
- **GPU Feature Discovery (GFD)**: a DaemonSet (or one-shot Job, since v0.19.0) that writes node labels / `NodeFeature` objects describing `count`, `product`, `memory` (MiB), `compute.major`/`minor`, `family`, `machine`, CUDA driver/runtime versions, `mode`, `clique`, and MIG-slice details, which drive node affinity (and NFD integration since v0.19.0). The GFD binary is beta. [GFD docs](https://github.com/NVIDIA/k8s-device-plugin/blob/main/docs/gpu-feature-discovery/README.md)
- **CDI and runtime integration**: the device plugin integrates with the NVIDIA Container Runtime/hook (installed by the Container Toolkit) and can generate CDI specs (`cdi.nvidiaHookPath`, `cdi.featureFlags`), letting CDI-enabled runtimes inject devices without the legacy hook path. [CDI notes](https://github.com/NVIDIA/k8s-device-plugin/blob/main/docs/cdi.md), [v0.18.1 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.18.1)
- **vGPU support**: when a node runs NVIDIA vGPU, the plugin exposes device information via `nvidia.com/vgpu.present`, `nvidia.com/vgpu.host-driver-branch`, and `nvidia.com/vgpu.host-driver-version` so workloads can select compatible drivers. [Catalog of Labels](https://github.com/NVIDIA/k8s-device-plugin#catalog-of-labels)
- **Tegra (Jetson) / integrated GPUs**: a CUDA-based resource manager exposes integrated devices on Tegra systems (since v0.13.0) and the `deviceDiscoveryStrategy` / driver-root flags (`nvidiaDriverRoot`) handle non-standard device paths; Tegra CUDA images use the CUDA base. [v0.13.0 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.13.0)
- **WSL (Windows Subsystem for Linux)**: on WSL nodes the device plugin reports a single `"all"` device to the kubelet (v0.19.1). [v0.19.1 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.19.1)
- **Per-node configuration**: configuration is selected per-node by the `nvidia.com/device-plugin.config` label pointing at a named entry in the integrated or external ConfigMap, enabling heterogeneous fleets (mixed MIG/sharing strategies across nodes). [passing configuration via a ConfigMap](https://github.com/NVIDIA/k8s-device-plugin#passing-configuration-to-the-plugin-via-a-configmap), [updating per-node configuration](https://github.com/NVIDIA/k8s-device-plugin#updating-per-node-configuration-with-a-node-label)
- **Configuration precedence and flags**: flags may be set as command-line flags or environment variables; precedence is flag > env > config file, and the full flag list (MIG, sharing, driver root, GDS/GDRCopy/MOFED, discovery strategy, etc.) is versioned per release. [as command-line flags or envvars](https://github.com/NVIDIA/k8s-device-plugin#as-command-line-flags-or-envvars)
- **Health and robustness**: `failOnInitError` controls failure when no devices are detected at startup (and since v0.13.0 the plugin fails on startup if no valid resources are detected); GPU health checks observe Xid events (configurable since v0.18.0). [v0.18.0 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.18.0)
- **Deployment variants**: Helm chart (repo `https://nvidia.github.io/k8s-device-plugin`) with subcharts for GFD and optional NFD, plus static manifests under [`deployments/static/`](https://github.com/NVIDIA/k8s-device-plugin/tree/main/deployments/static): the base `nvidia-device-plugin.yml`, a CPU-manager-compatible variant, a privileged variant with a ServiceAccount, the GFD DaemonSet (base, `mig-single`, `mig-mixed`), and a GFD Job template. [deployment](https://github.com/NVIDIA/k8s-device-plugin#deployment), [static manifests](https://github.com/NVIDIA/k8s-device-plugin/tree/main/deployments/static)
- **Security and base images**: images are built on the CUDA base image (now `distroless` golang builds since v0.18.0) in `ubuntu`/`ubi8`/`ubi9` flavours; RBAC is namespaced to GFD's node-label access (dedicated SA since v0.19.2); GFD and plugin run as DaemonSets with configurable `securityContext`, `priorityClassName`, and `runtimeClassName`. [image references](https://github.com/NVIDIA/k8s-device-plugin#image-references-for-nvidia-device-plugin), [v0.19.2 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.19.2)
- **Multi-architecture images**: multi-arch container images for `linux/amd64` and `linux/arm64` since v0.10.0, with general multi-arch image support added in v0.11.0. [v0.10.0 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.10.0), [v0.11.0 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.11.0)
- **IMEX domains**: inter-GPU memory (IMEX) domain labelling for NVLink fabric is no longer emitted by the plugin — the `nvidia.com/gpu.imex-domain` label was removed in v0.18.0; IMEX placement is handled outside the device plugin. [v0.18.0 release](https://github.com/NVIDIA/k8s-device-plugin/releases/tag/v0.18.0)
